# Bank statement import

On the Transactions screen, choose CSV / Excel, PDF, or Photo / Screenshot. Dragging a file onto the upload card also works. The statement automatically fills a review table with dates, descriptions, amounts, income/expense types, categories and payment methods. Every row has a category dropdown available immediately, before Import. Readable rows are selected by default. Check the table and choose Import. Edit is optional for corrections to other fields; Cancel edit restores that row's values from before editing. Saved imports update the transactions list and financial summaries.

Category suggestions recognize common food, grocery, transport, shopping, entertainment, utility, housing and healthcare descriptions in CSV, Excel, PDF and photo imports. Credits default to Income. Matching uses merchant/keyword boundaries so a name containing OLA does not automatically become Transport. Unrecognized payees and generic transfers stay in Other. Categories already supplied in a statement are preserved; custom categories remain available in the dropdown. The reviewed selection is saved exactly, including a deliberate choice of Other. No paid AI service is used for suggestions.

CSV and Excel support common bank headers, including Date / Transaction Date, Description / Narration / Particulars, separate Debit and Credit columns, or Amount with Type. Direction can also be filled from consistent running-balance changes and an opening balance, in ascending or descending date order. Amounts and balances must agree; ambiguous unsigned amounts are never guessed. Categories and payment methods are filled using the statement description when recognizable, with Other / Bank as defaults. Dates written as numbers in Excel use the workbook's calendar correctly. Text dates use Indian day/month/year order. A template is available on the upload card. Unreadable rows are visibly excluded and remain available for optional correction or a clearer re-upload.

PDF table extraction and photo/scanned-PDF text recognition run on the app server without an AI API key. Original PDF text coordinates preserve rows even when the file stores its text by column. Wrapped descriptions and amounts are joined, including digital transactions split across a page break. Column positions are retained on continuation pages without a header. Table geometry and OCR word positions preserve empty debit/credit cells; split monetary fragments are joined before reading amounts. OCR groups words on the same baseline across different text blocks, retries incomplete readings using sparse-text recognition, and also checks pages containing both digital text and images. No statement is sent to OpenAI or Gemini by this upload flow. A password is requested only when the uploaded PDF is protected. PDF passwords stay in memory during processing and are not saved to disk. Digital PDFs are read in memory. When a PDF requires text recognition, the original is temporarily cached privately while each scanned page is read in a separate bounded request. The upload card shows page progress and opens the review only after every required page finishes. Temporary files are deleted after completion/cancellation or after 30 minutes of inactivity; sessions are account-bound and must be restarted after an app-server restart. Only the selected transaction fields are saved to your existing Supabase account. The OCR engine uses the bundled eng.traineddata file without a network download. Small header/footer logos on readable digital pages do not trigger OCR. Table-grid detection runs only as a fallback for pages with incomplete native transaction rows; substantial image regions still receive OCR to catch scanned rows.

PDF completeness checks compare detected dated rows with the chosen extraction. A remaining gap is reported with the affected page number and row counts. Pages with no recognized transactions are also identified for review. These checks can flag possible omissions; they cannot prove completeness when the source itself is unreadable. Unknown or incomplete transaction details are never invented.

Statement limits: 50 MB per file, 500 pages per PDF, 10,000 rows per import. Larger files are rejected; pages are not silently truncated. Large reviewed imports are saved in one atomic operation, and the list refreshes when the database limits the number of returned rows. Supported image formats are PNG, JPG/JPEG and WebP. Clear scans work best. Unfamiliar or ambiguous layouts can require optional correction or a clearer export; automatic extraction cannot guarantee every bank layout or damaged/blurred document.

Repeated imports compare date, income/expense type, amount and normalized description against existing rows in your account. Matching counts are skipped while legitimate repeated rows within a statement are preserved. Duplicate checks must succeed before a single batch insert is attempted. Concurrent imports are serialized per account within one app process. Multiple deployment instances require a database-backed import identity/lock for the same concurrency guarantee. No new database migration is needed for this feature.

Validation: npm run test:imports checks category suggestions, unknown-payee handling, reviewed category persistence, CSV, Excel calendar systems and bank header aliases, balance-based direction inference across pages, numeric/direction validation, duplicate ownership and retries, concurrency, OCR column positions, wrapped/multiline rows and headers, actual text-PDF extraction and page limits. Regression checks also cover a 500-page digital statement with 10,000 rows, small logos and wide bank mastheads, scanned image regions, typed processing timeouts, simultaneous upload admission, and account-bound continuation sessions with file cleanup. To include local photo, bank table and scanned/mixed-PDF checks, set RUN_OCR_TESTS=1 before running the same command. Automated checks use synthetic fixtures, including a real two-page PDF with column-first storage and a transaction split across pages. Database insert/retry checks use a simulated account-scoped database.

Browser verification: an authenticated sample CSV displayed five populated rows with Food, Transport, Utilities, Income and Other automatically selected. Every category dropdown was enabled immediately. Changing Food to Other and the unknown transfer to Housing left Import enabled without clicking Edit. Server tests using a simulated database verified that reviewed choices reach storage unchanged. Targeted lint and the production build passed.

Open `/transactions` on your running app. Refresh an old tab after deployment to load the updated upload card. See [README.md](README.md) for local setup.
